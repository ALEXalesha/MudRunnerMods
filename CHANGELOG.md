# Changelog

## 1.1.0 - 16.10, not released yet (waiting for the in-game test)

After the 7th in-game test (11-16.10):
- **Powerful Engines 1.1.0 and Hyper Power 1.1.0: felt in every gear.** "Only 5th gear gives more" had a cause in the exe's gearbox (0x140922270): a gear gets `Torque / sqrt(max(AngVel/2, 1))` (high gear `Torque x 1.25`) times a wheel-speed curve that reaches zero at `2 x AngVel + 5` rad/s (high gear `AngVel + 2`), so more torque alone cannot move a gear past its speed band. Now Powerful Engines is `Torque` x3 and forward/high gear `AngVel` x1.5, Hyper Power `Torque` x10 (cap 1,000,000) and `AngVel` x2; `AngVel` is capped at the exe's 32 (new rows in `engine_limits.LIMITS`, read from the exe). Law `test_power_mods_are_felt_in_every_gear` (per truck and gear, with the exe's formula: torque at least x2.4 / x2.9, band x1.5 / x2, reverse stock) and `GearRulesTest` (the formula's constants read from the exe).
- **Big Fuel Tank "slow and heavy": not the mod.** The copy equals the stock truck except `FuelCapacity`; the exe adds fuel weight only through a `FuelMass` block (cisterns only). Law `BigTankMassTest`. Answer: the A-469 is a weak truck; use your own set with Powerful Engines.
- **Unlocked Trucks "nothing changed": not reproduced by files.** The maps' lock bytes are cleared, the package is mounted first, the exe reads the byte (`TerrainSTGLoad.cpp,471`) and checks it when placing a new game's trucks (0x14070b705). The profile has its own `status.unlockedTrucks` list and `status.isAllGaragesUnlocked` (slots and garage), which no file mod changes: that is for the profile tool. Asked the tester which lock it was.
- **Your own set: `Собрать свой мод.bat` + `tools/combine.py`.** Pick mods by number (Russian prompts), get ONE package `build/custom/opentrail_custom.zip` with one copy per truck "<truck> (Свой набор)" / "(Custom)", install with `install_local.py --custom --apply` (or right from the script), undo with `0` / `--remove`. Mods that change the same value (Powerful Engines and Hyper Power) are a question, not a silent overwrite (`build_mods.conflicts`, generic over all ops). Laws in `tests/test_combine.py` (sum of the parts on every truck, conflicts, names, package name). Custom trucks are now named "(Custom)" instead of "A + B".
- `title_ru` in every `mod.json`. 10 new mutations (54).
- **Open maps: `Открыть карты MudRunner.bat` + `tools/unlock_profile.py`.** Raises `profile.numLogPoints` in `UserProfile.stu` to the biggest map need in the exe (3), so Flood, Coast, River, Hill and DLC 3 map 2 are open. Game must be closed, dry run first, writes only after "да", backup before writing, `--restore`. Format parsed from the exe's STU loader (`tools/profile_stu.py`); law: the file parses again and only that field changes, every other byte identical; checked on the tester's profile copy too. 6 mutations (60).
- **Unlocked Trucks "the truck on the map stays locked": cause found (16.10 evening).** The locked trucks a new game shows on the map ("Drive closer to the truck to unlock it") are not in any level file. The tester's own save from the test (`level_volcano.sts`, written 01:02:59 while the mod was installed) has 3 open garage trucks and 4 locked ones (D-535, K-700, C-255, B-131) that the Volcano level file does not contain at all; they stand on the level's type-6 locators. The exe's new game picks 4 of those spots at random and spawns a random truck from a table in its code at each (0x1406e38d0), placed by the exe and never unlocked; they open only within 12 m. `engine_limits.RANDOM_TRUCK_*` + `read_exe_random_trucks`, law `RandomTruckCauseTest` (rules read from the exe, no level record near any spot on the 10 maps that have spots, the mod's description says what it does not do). The mod is unchanged (its package is byte for byte the same); its description now names the maps it does open (Flood, River, Valley, Ridge, Old-timers) and points to the tool for the rest.
- **Open trucks and garages in a map save: `Открыть карты MudRunner.bat`, items 2, 3 and 5 (new, item 1 and 4 unchanged).** `tools/save_sts.py` locates in `UserSaves/<map>.sts` (version 0x133efb9, from the exe's STS loader 0x14072c1a0) every truck header with its `isUnlocked` byte (the loader unlocks a truck when it is not 0, 0x14072cf85) and the garage list `{position, garage points}` (found by the level file's garage positions). Item 3 sets `isUnlocked = 1`, item 2 gives garages the 4 points they need, item 5 restores the save. Game must be closed, dry run first, writes after "да" only, backup in `%LOCALAPPDATA%\OpenTrail\MudRunner saves backup`, the written file is read back and only the planned bytes may differ. Laws in `tests/test_saves.py` (synthetic saves and, with `MUDRUNNER_SAVES_COPY`, copies of real saves: all 15 of the tester's saves parse with the exact truck count); 9 mutations (69).

## 1.0.0 - not released yet (waiting for the in-game test)

First version, built from the files of MudRunner 0.6.8 with all four DLC.

Mods (public names "OpenTrail ..."):
- **Hyper Power**: Motor Torque x10, capped at 1,000,000, on 36 trucks. Replaces Powerful Engines.
- **Powerful Engines**: Motor Torque x2.5.
- **AWD and Diff Lock**: wheels with Torque none or missing get full on 10 trucks; DiffLockType None becomes Default.
- **Deep Fording**: the damage sensation box moved 1 m above its old top.
- **No Damage**: Damage Capacity 64,000 (the exe's maximum).
- **Big Fuel Tank** (id `infinite_fuel`, was Infinite Fuel): FuelCapacity x4. The first version set 64,000 l and trucks jerked without moving (11.10): the exe cuts the engine at random when litres / FuelCapacity < 0.06, and a truck from the profile or a save brings its fuel in litres (a full stock tank was at most 1.25 %). Law `FuelFillLawTest`, thresholds read from the exe.
- **Grippy Wheels**: SubstanceFriction x2.5 (at least 2.5), BodyFriction x1.5 (at least 2.0) on 50 wheel types.
- **Winch Anchors**: winch sockets on 7 stumps and small trees.
- **Unlocked Trucks**: isLocked cleared for 24 trucks and trailers on 6 maps. Law per map (11.10): none of the 11 maps keeps a locked truck. The level head after the trucks is parsed (drive truck, locators, map frame). "Plains" has no locked truck; its second garage is locked by garage points, which are game state and exe code (4 points; free only within 64 m of the drive truck at a new game), so no file mod can open it. 4 new mutations (44, all caught).
- Not possible as a file mod: fog of war (saves and profile only), winch length and force, fuel consumption.

Fixed after the first in-game test (the game skipped the main menu and crashed on Esc): the Unlocked Trucks zip had Zip64 local headers that the game's PhysFS 2.0 rejects. Level files are now plain zip 2.0 entries; `tools/zipcheck.py` checks every package; `install_local.py` installs the safe set (without Unlocked Trucks) unless `--all` or `--mods` is given, and prints the list.

Fixed after the second in-game test (the game crashed on "Single player"): FuelCapacity 100,000 and Damage Capacity 1,000,000 were over the exe's limit of 64,000, Hyper Power torque over 1,000,000; the exe clamps such values and reports them through its XML error logger. `tools/engine_limits.py` holds the limits (read back from the exe in the tests) and the build stops on any value outside. Hyper Power is opt-in in `install_local.py` too.

Fixed after the third in-game test (single mods: plants and wheels work, truck files crash "Single player" and Esc): the six truck mods ship heir classes (`otf_kamaz4310` inherits `kamaz4310`) instead of replacing stock truck files; the build refuses a package that replaces one. Probe packages (`tools/build_probe.py`, `install_local.py --probe [changed]`).

Fifth in-game test (10.10): `--probe manifest`, `plant`, `wheel` work; `--probe truck` (one stock truck file, byte for byte) crashes at the truck menu; Infinite Fuel as full copies `otf_*` works. So all six truck mods ship full copies under new names (`oth_`, `otp_`, `ota_`, `otw_`, `otd_`, `otf_`; `otc_` for `--only`) with the stock selection icon and display names in new strings files `strings/<lang>/opentrail_<mod>.txt` (12 languages, Russian suffix in `ru`; `build_mods.py --no-names` leaves them out). A truck mod package ships no stock path at all, no package a stock truck file (`forbidden_files`, also for custom packages). New law `tests/test_truck_law.py`: no mod writes to `classes/trucks/<stock name>.xml`, checked independently of the build's guard on every output; 7 new mutations (34, all caught). New probe `--probe names`; `--probe truck`, `identical` and `changed` are marked in `--help` and the output as deliberately crashing, diagnosis only. Workshop folders: full copies with icons (no `<_parent>`), description text updated.

The real cause of every in-game crash (found 11.10 in the crash dumps, 18 WER reports and 10 dumps, all MSVCR110.dll+0x6d5ff, c0000409): the exe copies the name of the zip a truck or level comes from into a 17-byte buffer with `strncpy_s`; our names (`OpenTrail_Infinite_Fuel`, 23 characters) were too long. Packages are now `opentrail_<short>.zip` and probes `otprobe_<name>.zip`, at most 16 characters before `.zip`; `engine_limits.ARCHIVE_NAME_MAX` (read back from the exe), a build check and the law `tests/test_archive_names.py`; 4 new mutations (38, all caught). The earlier explanations (Zip64, engine limits, stock truck files) were not the crash; their changes stay. `--probe truck` is no longer called "always crashes": with a short name it is the open question of the 7th test.

Tools: tolerant class XML parser and inheritance resolver, local packages for Config.xml MediaPath, custom packages (`--only`), Workshop folders for the MudRunner Editor (new base-game trucks as full copies), Config.xml installer with backup, test suite and mutation check.
