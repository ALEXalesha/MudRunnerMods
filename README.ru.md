# MudRunnerMods

OpenTrail: моды геймплея для Spintires: MudRunner, собранные из файлов самой игры, и инструменты, которые их собирают и проверяют.

> Не связано с Saber Interactive и Focus Entertainment и не одобрено ими. «Spintires: MudRunner» - их товарный знак. Моды любительские, для одиночной игры.

[English version](README.md)

Файлов игры в репозитории нет. `tools/build_mods.py` читает XML классов из установленной игры (`Media.zip` и четыре архива DLC), меняет только нужное и пишет по одному пакету-замене на мод. После обновления игры сборку нужно запустить заново.

## Моды

Десять идей, девять модов. Туман войны файлами игры не убрать (см. «Что невозможно»).

| Мод (пакет) | Что меняет | Охват |
|---|---|---|
| Hyper Power (`OpenTrail_Hyper_Power.zip`) | `Motor@Torque` x10, ради веселья. Заменяет Powerful Engines | 36 грузовиков, база + DLC |
| Powerful Engines (`OpenTrail_Powerful_Engines.zip`) | `Motor@Torque` x2,5 (в игре 16 000 - 240 000) | 36 грузовиков |
| AWD and Diff Lock (`OpenTrail_AWD_and_Diff_Lock.zip`) | Колёса с `Torque="none"` или без Torque получают `full`; `DiffLockType="None"` становится `Default` (включаемая) | 10 грузовиков (9 файлов) |
| Deep Fording (`OpenTrail_Deep_Fording.zip`) | Зона `Damage@SensationMin/Max` поднята на 1 м выше прежнего верха (высота 0,2 м) | 36 грузовиков |
| No Damage (`OpenTrail_No_Damage.zip`) | `Damage@Capacity` 1 000 000 (в игре 160 - 1000) | 36 грузовиков |
| Infinite Fuel (`OpenTrail_Infinite_Fuel.zip`) | `TruckData@FuelCapacity` 100 000 л (в игре 40 - 800) | 36 грузовиков |
| Grippy Wheels (`OpenTrail_Grippy_Wheels.zip`) | `WheelFriction@SubstanceFriction` x2,5, не меньше 2,5; `@BodyFriction` x1,5, не меньше 2,0 | 50 типов колёс |
| Winch Anchors (`OpenTrail_Winch_Anchors.zip`) | `GameData/WinchSocket` у 7 пней и маленьких деревьев, где точек не было | 7 растений |
| Unlocked Trucks (`OpenTrail_Unlocked_Trucks.zip`, 295 МБ) | снят `isLocked` в записях грузовиков в файлах уровней | 24 грузовика и прицепа на 6 картах |

### Почему так

**Infinite Fuel - большой бак, а не нулевой расход.** Ни в одном файле грузовика и ни в одном имени атрибута в exe нет расхода топлива: его считает код игры (в интерфейсе только `%d L / Min`). Бак на 100 000 л - максимум, что можно сделать файлом: при 20 л/мин это больше 80 часов езды. Топливо на старте карты хранится в процентах (`fFuel` 0-100 в файле уровня), так что грузовики стартуют с полным баком. Баки дополнений и цистерны не меняются.

**No Damage - огромный запас, а не 0.** Игра делит повреждения на `Capacity` (коэффициент повреждений в `truck.lua`, надпись `Damage: %d/%d`). Ноль - деление на ноль, урок ETS2, где нулевой расход дал `-nan` на приборной панели. С 1 000 000 грузовик никогда не подходит к порогу 0,7, после которого `truck.lua` включает эффекты повреждений.

**Deep Fording поднимает зону повреждений.** В официальном руководстве сказано, что эта зона «также используется для проверки перелива воды». Зона на 1 м выше прежнего верха: вода должна подняться намного выше кабины, прежде чем грузовик получит повреждение от воды или заглохнет. По той же зоне считаются удары, поэтому кабина почти не получает повреждений и от ударов. Пример ЗИЛ-130: Y 1,57-2,17 стало 3,17-3,37.

**AWD: что значат none и отсутствие Torque.** `Wheel@Torque`: `default` (ведущее всегда), `full` (ведущее при включённом полном приводе), `none`. У грузовиков 4x2 (B-130, A-968m, UMZ) у передних колёс Torque нет вовсе, значит «нет» тоже означает «не ведущее». Постоянный полный привод и постоянная блокировка (`Always`) остаются как были.

| Грузовик | Передние колёса | Блокировка |
|---|---|---|
| kamaz65115 (C-65115), kraz256 (C-256) | none -> full | kamaz65115: None -> Default |
| zil130 (B-130), zaz968m (A-968m) | нет -> full | None -> Default |
| chevrolet_bison_1978, ford_ltl9000, freightliner_fl120, gmc_dw950 (DLC) | none -> full | без изменений |
| umz6a (The Ridge) | нет -> full | без изменений (Always) |

**Grippy Wheels.** Большинство колёс берут трение из шаблонов `_templates/trucks.xml`; мод пишет оба значения в каждый класс колеса, а общий файл шаблонов не трогает: Offroad 1,0/1,2 -> 2,0/3,0; Default 1,25/0,75 -> 2,0/2,5; Highway 1,5/0,5 -> 2,25/2,5; явные Substance 1,6/1,8 -> 4,0/4,5.

**Winch Anchors, а не длинная лебёдка.** Длины и силы лебёдки нет ни в одном файле: в exe трос - это верёвочное ограничение Havok. Файлом можно поменять только то, за что лебёдка цепляется. У всех грузовиков и прицепов точки есть и в обычной игре; у семи растений их не было: `stump_b`, `small_tree_a`-`small_tree_d`, `fir_small_b`, `pine_small_b`. Маленькое дерево при сильной тяге можно вырвать, как и раньше.

**Unlocked Trucks правит файлы уровней.** Загрузчик уровней в exe читает для каждого грузовика на карте имя типа, матрицу, дополнения, прицеп, повреждение, топливо и байт `isLocked`. Мод копирует шесть карт, где есть запертые грузовики (Coast, Flood, River, The Ridge, The Valley, Old-timers), и обнуляет только эти байты (проверено побайтно). Испытания, обучение и полигон не трогаются. Действует для новой игры или перезапущенной карты; в старых сохранениях состояние грузовиков своё.

## Что невозможно обычным модом

| Идея | Почему | Варианты |
|---|---|---|
| Без тумана войны / открытая карта | Карта тумана (cloaking) есть только в сохранениях (`.sts`: `nCloakingWidth`, `cloakingData`) и в профиле (`UserProfile.stu`: мини-карта). В файлах уровней её нет. | Править сохранение при закрытой игре (обнулить `cloakingData`); или доехать до смотровых точек; трюк с файлом уровня (перенести смотровую точку к старту и расширить) не проверен и засчитал бы достижения, поэтому не сделан |
| Длинная и сильная лебёдка | Атрибута нет (см. выше) | Только патч exe, это вне задачи |
| Нулевой расход топлива | В файлах нет (см. выше) | Большой бак |
| Грузовики, открытые для стартовых слотов | Хранятся в профиле (`status.unlockedTrucks`) | Не трогается; Unlocked Trucks открывает грузовики на картах |

## Установка (локальные пакеты)

Игра читает дополнительные файлы через строки `<MediaPath>` в Config.xml. Берётся первая найденная копия файла, поэтому пакеты ставятся выше `Media.zip`.

1. Собрать (или взять zip из релиза):
   ```
   uv venv .venv && uv pip install --python .venv\Scripts\python.exe -r tools\requirements.txt
   .venv\Scripts\python tools\build_mods.py
   ```
   Пакеты появятся в `build\local\`.
2. Закрыть игру. Посмотреть, что изменится, и записать:
   ```
   .venv\Scripts\python tools\install_local.py
   .venv\Scripts\python tools\install_local.py --apply
   .venv\Scripts\python tools\install_local.py --mods no_damage,infinite_fuel --apply
   ```
   Скрипт правит `%APPDATA%\SpinTires MudRunner\Config.xml` (его игра сохраняет при выходе), убирает старые строки OpenTrail, вставляет новые над `<MediaPath Path="Media.zip" />` в порядке загрузки ниже и оставляет рядом копию `Config.xml.opentrail-<время>`.

   Вручную: добавить строки вида `<MediaPath Path="D:/Games/OpenTrail/OpenTrail_No_Damage.zip" />` над `<MediaPath Path="Media.zip" />`.
3. Запустить игру. В `%APPDATA%\SpinTires MudRunner\Log.txt` для каждого пакета должна быть строка `MediaPath '...OpenTrail_...zip' added.` `Cant add MediaPath` - неверный путь.
4. Для Unlocked Trucks начать новую игру на карте.
5. Убрать: `install_local.py --remove --apply` или удалить строки.

Только одиночная игра: для сетевой игры exe сравнивает хэши файлов грузовиков, колёс и шаблонов.

## Порядок загрузки и общие файлы

Сверху вниз (`mods/order.json`), в том же порядке идут строки MediaPath:

1. Hyper Power (или выключить и взять Powerful Engines)
2. Powerful Engines (выключить, если включён Hyper Power)
3. AWD and Diff Lock
4. Deep Fording
5. No Damage
6. Infinite Fuel
7. Grippy Wheels
8. Winch Anchors
9. Unlocked Trucks

Шесть модов меняют одни и те же файлы грузовиков. Игра берёт только первую копию, поэтому каждый мод несёт ещё и правки всех модов ниже по списку, и при включённых всех ничего не теряется. Hyper Power заменяет Powerful Engines и его x2,5 не несёт (момент x10 от обычного, а не x25). Обратная сторона: мод в одиночку приносит и правки нижних модов в общих файлах. Например, один Deep Fording даёт ещё No Damage и Infinite Fuel. Чтобы взять ровно нужные моды, соберите свой пакет:

```
.venv\Scripts\python tools\build_mods.py --only awd_difflock,grippy_wheels
```

Получится `build\local\OpenTrail_Custom.zip` только с этими правками.

## Мастерская Steam

Моды MudRunner загружаются в Мастерскую через MudRunner Editor, а он при публикации переименовывает все файлы, поэтому предмет Мастерской не может заменить файл игры. Версии для Мастерской поэтому добавляют новые грузовики, которые наследуют обычные (`<_parent File="kamaz4310" />`) с изменением, с именами вида «C-65115 (AWD)». Их выбирают в слотах при старте карты или вызывают на полигоне. Варианты есть только у грузовиков базовой игры: игра проверяет владение DLC по имени ассета, и переименованный DLC-грузовик мог бы эту проверку обойти. У Winch Anchors и Unlocked Trucks версии для Мастерской нет: они меняют только файлы игры.

`.venv\Scripts\python tools\build_workshop.py` пишет `workshop\NN_OpenTrail_<Имя>\` (7 папок) и файлы релиза. Как загружать: [WORKSHOP.md](WORKSHOP.md).

## Тесты

```
.venv\Scripts\python -m unittest discover -s tests -v
.venv\Scripts\python tools\mutation_check.py
```

Проверяется: у каждого из 36 грузовиков (20 база, 16 DLC) и 50 типов колёс эффективное значение мода, для каждого пакета отдельно и для всех вместе в порядке загрузки; каждый файл разбирается, структура элементов не меняется, меняются только нужные атрибуты; ни одно значение-делитель не равно 0; цепочка общих файлов; Hyper Power x10, а не x25; все 25 уровней разбираются, а разблокировка меняет ровно байты `isLocked`; папки Мастерской (только .xml и .png, имена, strings.xml, превью 512x512, CRLF, наследники дают ровно нужные значения, родители только из базовой игры); правка Config.xml на копии; нет личных данных; законы парсера на сгенерированном XML (hypothesis). `tools/mutation_check.py` ломает продукт в 21 месте во временной копии и проверяет, что нужный тест каждый раз падает.
