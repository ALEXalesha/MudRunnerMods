# MudRunnerMods

OpenTrail: моды геймплея для Spintires: MudRunner, собранные из файлов самой игры, и инструменты, которые их собирают и проверяют.

> Не связано с Saber Interactive и Focus Entertainment и не одобрено ими. «Spintires: MudRunner» - их товарный знак. Моды любительские, для одиночной игры.

[English version](README.md)

Файлов игры в репозитории нет. `tools/build_mods.py` читает XML классов из установленной игры (`Media.zip` и четыре архива DLC), меняет только нужное и пишет по одному пакету-замене на мод. После обновления игры сборку нужно запустить заново.

## Моды

Десять идей, девять модов. Туман войны файлами игры не убрать (см. «Что невозможно»).

**После третьей проверки в игре шесть модов грузовиков добавляют НОВЫЕ грузовики** (наследники обычных, например `otf_kamaz4310` - C-4310 с Infinite Fuel), а не подменяют файлы обычных грузовиков: подмена `classes/trucks/*.xml` роняла игру на «Одиночной игре». Новые грузовики выбирают в слотах при старте карты или вызывают на полигоне; грузовики, стоящие на картах, остаются обычными. Grippy Wheels, Winch Anchors и Unlocked Trucks по-прежнему подменяют файлы колёс, растений и уровней (подмена колёс и растений проверена в игре и работает).

| Мод (пакет) | Что меняет | Охват |
|---|---|---|
| Hyper Power (`OpenTrail_Hyper_Power.zip`) | `Motor@Torque` x10, но не больше 1 000 000 (предел игры), ради веселья. Заменяет Powerful Engines; по выбору | 36 грузовиков, база + DLC |
| Powerful Engines (`OpenTrail_Powerful_Engines.zip`) | `Motor@Torque` x2,5 (в игре 16 000 - 240 000) | 36 грузовиков |
| AWD and Diff Lock (`OpenTrail_AWD_and_Diff_Lock.zip`) | Колёса с `Torque="none"` или без Torque получают `full`; `DiffLockType="None"` становится `Default` (включаемая) | 10 грузовиков (9 файлов) |
| Deep Fording (`OpenTrail_Deep_Fording.zip`) | Зона `Damage@SensationMin/Max` поднята на 1 м выше прежнего верха (высота 0,2 м) | 36 грузовиков |
| No Damage (`OpenTrail_No_Damage.zip`) | `Damage@Capacity` 64 000 - максимум игры (в игре 160 - 1000) | 36 грузовиков |
| Infinite Fuel (`OpenTrail_Infinite_Fuel.zip`) | `TruckData@FuelCapacity` 64 000 л - максимум игры (в игре 40 - 800) | 36 грузовиков |
| Grippy Wheels (`OpenTrail_Grippy_Wheels.zip`) | `WheelFriction@SubstanceFriction` x2,5, не меньше 2,5; `@BodyFriction` x1,5, не меньше 2,0 | 50 типов колёс |
| Winch Anchors (`OpenTrail_Winch_Anchors.zip`) | `GameData/WinchSocket` у 7 пней и маленьких деревьев, где точек не было | 7 растений |
| Unlocked Trucks (`OpenTrail_Unlocked_Trucks.zip`, 295 МБ) | снят `isLocked` в записях грузовиков в файлах уровней | 24 грузовика и прицепа на 6 картах |

### Почему так

**Infinite Fuel - большой бак, а не нулевой расход.** Ни в одном файле грузовика и ни в одном имени атрибута в exe нет расхода топлива: его считает код игры (в интерфейсе только `%d L / Min`). Бак на 64 000 л - максимум, что можно сделать файлом: exe ограничивает FuelCapacity числом 64 000 (см. «Пределы движка»). При 20 л/мин это больше 50 часов езды. Топливо на старте карты хранится в процентах (`fFuel` 0-100 в файле уровня), так что грузовики стартуют с полным баком. Баки дополнений и цистерны не меняются.

**No Damage - огромный запас, а не 0.** Игра делит повреждения на `Capacity` (коэффициент повреждений в `truck.lua`, надпись `Damage: %d/%d`). Ноль - деление на ноль, урок ETS2, где нулевой расход дал `-nan` на приборной панели. С 64 000 (максимум exe, в 64 раза больше самого крепкого обычного грузовика) грузовик никогда не подходит к порогу 0,7, после которого `truck.lua` включает эффекты повреждений.

**Deep Fording поднимает зону повреждений.** В официальном руководстве сказано, что эта зона «также используется для проверки перелива воды». Зона на 1 м выше прежнего верха: вода должна подняться намного выше кабины, прежде чем грузовик получит повреждение от воды или заглохнет. По той же зоне считаются удары, поэтому кабина почти не получает повреждений и от ударов. Пример ЗИЛ-130: Y 1,57-2,17 стало 3,17-3,37.

**AWD: что значат none и отсутствие Torque.** `Wheel@Torque`: `default` (ведущее всегда), `full` (ведущее при включённом полном приводе), `none`. У грузовиков 4x2 (B-130, A-968m, UMZ) у передних колёс Torque нет вовсе, значит «нет» тоже означает «не ведущее». Постоянный полный привод и постоянная блокировка (`Always`) остаются как были.

| Грузовик | Передние колёса | Блокировка |
|---|---|---|
| kamaz65115 (C-65115), kraz256 (C-256) | none -> full | kamaz65115: None -> Default |
| zil130 (B-130), zaz968m (A-968m) | нет -> full | None -> Default |
| chevrolet_bison_1978, ford_ltl9000, freightliner_fl120, gmc_dw950 (DLC) | none -> full | без изменений |
| umz6a (The Ridge) | нет -> full | без изменений (Always) |

**Grippy Wheels.** Большинство колёс берут трение из шаблонов `_templates/trucks.xml`; мод пишет оба значения в каждый класс колеса, а общий файл шаблонов не трогает: Offroad 1,0/1,2 -> 2,0/3,0; Default 1,25/0,75 -> 2,0/2,5; Highway 1,5/0,5 -> 2,25/2,5; явные Substance 1,6/1,8 -> 4,0/4,5.

**Winch Anchors, а не длинная лебёдка.** Длины и силы лебёдки нет ни в одном файле: в exe трос - это верёвочное ограничение Havok. Файлом можно поменять только то, за что лебёдка цепляется. У всех грузовиков и прицепов точки есть и в обычной игре; у семи растений их не было: `stump_b`, `small_tree_a`-`small_tree_d`, `fir_small_b`, `pine_small_b`. Маленькое дерево при сильной тяге можно вырвать, как и раньше.

**Unlocked Trucks правит файлы уровней.** Загрузчик уровней в exe читает для каждого грузовика на карте имя типа, матрицу, дополнения, прицеп, повреждение, топливо и байт `isLocked`. Мод копирует шесть карт, где есть запертые грузовики (Coast, Flood, River, The Ridge, The Valley, Old-timers), и обнуляет только эти байты (проверено побайтно). Испытания, обучение и полигон не трогаются. Действует для новой игры или перезапущенной карты; в старых сохранениях состояние грузовиков своё.

## Что невозможно обычным модом

| Идея | Почему | Варианты |
|---|---|---|
| Без тумана войны / открытая карта | Карта тумана (cloaking) есть только в сохранениях (`.sts`: `nCloakingWidth`, `cloakingData`) и в профиле (`UserProfile.stu`: мини-карта). В файлах уровней её нет. | Править сохранение при закрытой игре (обнулить `cloakingData`); или доехать до смотровых точек; трюк с файлом уровня (перенести смотровую точку к старту и расширить) не проверен и засчитал бы достижения, поэтому не сделан |
| Длинная и сильная лебёдка | Атрибута нет (см. выше) | Только патч exe, это вне задачи |
| Нулевой расход топлива | В файлах нет (см. выше) | Большой бак |
| Грузовики, открытые для стартовых слотов | Хранятся в профиле (`status.unlockedTrucks`) | Не трогается; Unlocked Trucks открывает грузовики на картах |

## Установка (локальные пакеты)

Игра читает дополнительные файлы через строки `<MediaPath>` в Config.xml. Берётся первая найденная копия файла, поэтому пакеты ставятся выше `Media.zip`.

1. Собрать (или взять zip из релиза):
   ```
   uv venv .venv && uv pip install --python .venv\Scripts\python.exe -r tools\requirements.txt
   .venv\Scripts\python tools\build_mods.py
   ```
   Пакеты появятся в `build\local\`.
2. Закрыть игру. Посмотреть, что изменится, и записать:
   ```
   .venv\Scripts\python tools\install_local.py
   .venv\Scripts\python tools\install_local.py --apply
   .venv\Scripts\python tools\install_local.py --all --apply
   .venv\Scripts\python tools\install_local.py --mods no_damage,infinite_fuel --apply
   ```
   Без `--mods` ставится безопасный набор: все моды, кроме тех, что по выбору (`"opt_in"` в `mods/order.json`: Hyper Power - замена Powerful Engines, и Unlocked Trucks - он подменяет целые файлы уровней). `--all` добавляет и их. Скрипт печатает, какие моды ставит и какие нет. Скрипт правит `%APPDATA%\SpinTires MudRunner\Config.xml` (его игра сохраняет при выходе), убирает старые строки OpenTrail, вставляет новые над `<MediaPath Path="Media.zip" />` в порядке загрузки ниже и оставляет рядом копию `Config.xml.opentrail-<время>`.

   Вручную: добавить строки вида `<MediaPath Path="D:/Games/OpenTrail/OpenTrail_No_Damage.zip" />` над `<MediaPath Path="Media.zip" />`.
3. Запустить игру. Нынешняя сборка игры больше не пишет `%APPDATA%\SpinTires MudRunner\Log.txt` (он с января 2026 и не обновляется даже после обычного запуска без модов, хотя профиль и Config.xml перезаписываются), а падение не оставляет локального дампа (exe отдаёт его в `SteamAPI_WriteMiniDump`, в `Steam\dumps` от MudRunner ничего нет). Поэтому проверка - в игре: главное меню появляется как обычно, а с Infinite Fuel у грузовика бак 64000 л.
4. Для Unlocked Trucks начать новую игру на карте.
5. Убрать: `install_local.py --remove --apply` или удалить строки.

Только одиночная игра: для сетевой игры exe сравнивает хэши файлов грузовиков, колёс и шаблонов.

## Что сломалось в первой проверке и закон про zip

Первая проверка 1.0.0 в игре (все девять пакетов) не дошла до главного меню: игра сразу попадала на карту и падала по Esc. Без пакетов всё работало. Причина найдена без запуска игры: zip с Unlocked Trucks. Потоковая запись zip в Python с `force_zip64=True` записала шесть файлов уровней с локальными заголовками Zip64 (версия 4.5, размеры 0xFFFFFFFF, поле Zip64), а в центральном каталоге стояли настоящие размеры. MudRunner читает zip через PhysFS 2.0 (её сообщения «ZIP bigger than 2 gigs?!» и «Corrupted archive» есть в exe). Эта версия не знает Zip64 и перед открытием файла сверяет локальный заголовок с центральным каталогом, поэтому все шесть уровней оказались «повреждёнными». Путь принадлежит первому архиву, где он есть, так что к Media.zip игра тоже не вернулась.

`tools/zipcheck.py` проверяет эти правила PhysFS 2.0: нигде нет Zip64, локальный заголовок совпадает с центральным каталогом (версия, метод, CRC, размеры), только deflate или store, меньше 2 ГБ. Media.zip, архивы DLC, MeshCache.zip и все 8 предметов Мастерской на этом ПК проходят; пакет уровней 1.0.0 не прошёл (24 нарушения). Теперь сборка проверяет каждый пакет и останавливается при нарушении, а уровни пишутся обычными записями zip 2.0 (размер задаётся заранее). Пакеты с файлами классов были в порядке.

## Пределы движка (вторая проверка в игре)

С безопасным набором главное меню открылось, но игра падала на «Одиночной игре» - экране, который загружает грузовики карт. Побайтное сравнение каждого файла пакетов с файлом игры ничего не нашло (та же кодировка, без BOM, те же концы строк, те же элементы, меняются только нужные атрибуты). Причина в exe: часть атрибутов он читает с проверкой диапазона, значение вне диапазона обрезает и сообщает об этом через логгер ошибок XML («| Clamping node %s value %d (maximum is %d)»). Три мода выходили за пределы:

| Атрибут | Предел exe | В 1.0.0 | Теперь |
|---|---|---|---|
| TruckData FuelCapacity | макс. 64 000 (`cmp reg, 0xFA00`) | 100 000 (Infinite Fuel) | 64 000 |
| Damage Capacity | макс. 64 000 | 1 000 000 (No Damage) | 64 000 |
| Motor Torque | макс. 1 000 000 | до 2 400 000 (Hyper Power x10) | x10, но не больше 1 000 000 |
| WheelFriction Substance / Body | 0,1 - 10,0 | до 4,5 | без изменений |

`tools/engine_limits.py` хранит таблицу и читает те же числа из установленного exe; сборка останавливается на любом значении вне её, а тесты проверяют каждый грузовик и колесо каждого пакета, все пакеты вместе и варианты для Мастерской.

### Пакет-проба и кэши

`tools/build_probe.py` пишет `OpenTrail_Probe_Identical.zip`: три файла игры (грузовик, колесо, растение), скопированные байт в байт, в том же формате zip. `install_local.py --probe --apply` подключает только его. Если с ним игра работает, сам механизм подключения в порядке.

Кэши текстур и мешей (`TextureCache.zip` как `_t/`, `MeshCache.zip` как `_m/`) ключуются по именам мешей и текстур (`_m/trucks_kamaz4310`); exe дальше смотрит в `MeshCache/` и в исходные папки `meshes/` / `textures/`. XML классов ни в какой кэш не входят, а пакеты не везут ни мешей, ни текстур, поэтому изменённый XML грузовика не может сделать запись кэша устаревшей. Предметы Мастерской везут свои `_m/` и `_t/` только потому, что приносят новые меши.

## Третья проверка в игре: файлы обычных грузовиков подменять нельзя

Пробы по одному моду: один Winch Anchors (файлы растений) и один Grippy Wheels (файлы колёс) работают; один Infinite Fuel (файлы грузовиков, изменён только `FuelCapacity`, 64 000, в пределах) падает на «Одиночной игре» и по Esc. Побайтное сравнение: больше в этих файлах ничего не изменено. Значит, сама подмена класса обычного грузовика и есть проблема. Вероятный механизм по exe: сохранения и профиль хранят контрольную сумму каждого грузовика (`dwTruckCRC`), загрузчик пропускает грузовик, чей XML изменился («Not loading truck %d because XML or mesh has changed»); экран «Одиночная игра» читает сохранения (активные грузовики карт), меню по Esc тоже. Пробы, чтобы отделить это от самого подключения:

```
.venv\Scripts\python tools\build_probe.py
.venv\Scripts\python tools\install_local.py --probe --apply            (3 файла игры байт в байт)
.venv\Scripts\python tools\install_local.py --probe changed --apply    (uaz469.xml, FuelCapacity 80 -> 81)
```

Исправление в любом случае одно: моды грузовиков везут наследников со своими именами (`otf_`, `otd_`, `otp_`, `oth_`, `ota_`, `otw_`; общий `otc_` для `--only`), ровно как предметы Мастерской, и ни один файл обычного грузовика не подменяется. Сборка останавливается, если пакет подменил бы такой файл, и тест проверяет каждый пакет. Перед проверкой стоит сделать копию `%APPDATA%\SpinTires MudRunner\UserSaves`: игра перезаписала сохранение во время запуска с модами (cnt6vfqa.sts, 04.10 01:26).

## Порядок загрузки и общие файлы

Сверху вниз (`mods/order.json`), в том же порядке идут строки MediaPath:

1. Hyper Power (или выключить и взять Powerful Engines)
2. Powerful Engines (выключить, если включён Hyper Power)
3. AWD and Diff Lock
4. Deep Fording
5. No Damage
6. Infinite Fuel
7. Grippy Wheels
8. Winch Anchors
9. Unlocked Trucks

Шесть модов меняют одни и те же файлы грузовиков. Игра берёт только первую копию, поэтому каждый мод несёт ещё и правки всех модов ниже по списку, и при включённых всех ничего не теряется. Hyper Power заменяет Powerful Engines и его x2,5 не несёт (момент x10 от обычного, а не x25). Обратная сторона: мод в одиночку приносит и правки нижних модов в общих файлах. Например, один Deep Fording даёт ещё No Damage и Infinite Fuel. Чтобы взять ровно нужные моды, соберите свой пакет:

```
.venv\Scripts\python tools\build_mods.py --only awd_difflock,grippy_wheels
```

Получится `build\local\OpenTrail_Custom.zip` только с этими правками.

## Мастерская Steam

Моды MudRunner загружаются в Мастерскую через MudRunner Editor, а он при публикации переименовывает все файлы, поэтому предмет Мастерской не может заменить файл игры. Версии для Мастерской поэтому добавляют новые грузовики, которые наследуют обычные (`<_parent File="kamaz4310" />`) с изменением, с именами вида «C-65115 (AWD)». Их выбирают в слотах при старте карты или вызывают на полигоне. Варианты есть только у грузовиков базовой игры: игра проверяет владение DLC по имени ассета, и переименованный DLC-грузовик мог бы эту проверку обойти. У Winch Anchors и Unlocked Trucks версии для Мастерской нет: они меняют только файлы игры.

`.venv\Scripts\python tools\build_workshop.py` пишет `workshop\NN_OpenTrail_<Имя>\` (7 папок) и файлы релиза. Как загружать: [WORKSHOP.md](WORKSHOP.md).

## Тесты

```
.venv\Scripts\python -m unittest discover -s tests -v
.venv\Scripts\python tools\mutation_check.py
```

Проверяется: у каждого из 36 грузовиков (20 база, 16 DLC) и 50 типов колёс эффективное значение мода, для каждого пакета отдельно и для всех вместе в порядке загрузки; каждый файл разбирается, структура элементов не меняется, меняются только нужные атрибуты; ни одно значение-делитель не равно 0; цепочка общих файлов; Hyper Power x10, а не x25; все 25 уровней разбираются, а разблокировка меняет ровно байты `isLocked`; папки Мастерской (только .xml и .png, имена, strings.xml, превью 512x512, CRLF, наследники дают ровно нужные значения, родители только из базовой игры); правка Config.xml на копии; нет личных данных; законы парсера на сгенерированном XML (hypothesis). `tools/mutation_check.py` ломает продукт в 27 местах во временной копии и проверяет, что нужный тест каждый раз падает.
